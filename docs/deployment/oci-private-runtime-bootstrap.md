# OCI private integrated runtime bootstrap

Deploys integrated app + PostgreSQL 16/PostGIS to an existing OCI private host. Does not provision OCI, format disks, expose public ports, configure TLS, or authorize real data.

Prerequisites: identity-verified volumes mounted at `/var/lib/claim2car/postgres` (UID/GID 10001, mode 0750) and `/var/lib/claim2car/evidence` (UID/GID 10001, mode 0700); Podman/curl/mountpoint; ARM64 host; published immutable OCIR image; least-privilege registry auth token.

Install the source checkout on the host with `git clone https://github.com/C2C-Connect/claim2car-connect.git /opt/claim2car` and checkout the commit corresponding to the published image. Then, first boot as root: `python3 scripts/oci_staging_runtime_bootstrap.py --dir /etc/claim2car/runtime`. Generates high-entropy DB credentials, one synthetic tenant, owner/operator/reviewer tokens (180 days), VIN pepper, internal token, init SQL and runtime config. Secret files 0600, runtime config 0640 (group 10001), directory 0700. Securely deliver tokens, then delete token file. Never rerun on initialized database; generated passwords won't match. Refuses overwriting any non-empty output directory; it will not rotate initialized database credentials. The generated `runtime.env` also contains empty optional Square Sandbox environment entries; checkout/webhook secrets can be configured there by the authorized host operator without being placed in the capture runtime JSON or source repository.

Set `OCI_IMAGE_REF` to digest-pinned OCIR ref including `:sha-<40-character-commit>@sha256:<digest>`, `C2C_POSTGRES_IMAGE` to a PostGIS image pinned by `@sha256:<64-hex-digest>`, `OCI_REGISTRY`, `OCI_REGISTRY_USERNAME`, and `OCI_REGISTRY_TOKEN`; optional loopback port `C2C_STAGING_LOOPBACK_PORT`. Source root-only env and run `sudo -E scripts/oci_staging_runtime_deploy.sh`. The deploy script refuses mutable PostGIS tags, symlinked/missing mount roots, shared volume sources, unexpected ownership, or bootstrap files with unsafe permissions. OCIR authentication uses a root-only temporary auth file under `/run` (tmpfs), removes it immediately after both image pulls, and cleans it on failure; registry tokens are not written to the persistent Podman auth store. Existing DB containers are only reused if their data mount and image identity match the requested pinned image; otherwise it stops before changing database state.

Script checks both persistent mounts, UID/GID and modes, pulls ARM64 images, starts PostGIS with loopback-only DB port, applies the current authority migration plan through 0026, seeds synthetic tenant/login binding, and starts the app as UID/GID 10001 with a read-only root filesystem, all capabilities dropped, no-new-privileges, and a bounded non-executable /tmp. The app entrypoint verifies evidence mount ownership/mode and does not attempt to mutate it when launched non-root. Verifies readiness/build identity; on failure stops the new app and attempts rollback to the prior image. Database migrations are not rolled back; migration compatibility must be reviewed before each release. Never formats disks or deletes data.

Optional Sandbox configuration may be injected only through the approved runtime secret store: `SQUARE_ENVIRONMENT=sandbox`, `SQUARE_SANDBOX_ACCESS_TOKEN`, `SQUARE_SANDBOX_LOCATION_ID`, `SQUARE_SANDBOX_WEBHOOK_SIGNATURE_KEY`, and `SQUARE_SANDBOX_WEBHOOK_URL`. Do not put Square secrets in the generated bootstrap directory or source repository; provider webhook delivery is not reachable from the private host without a separately reviewed relay.

Constraints: single synthetic tenant only; DB login `faos_app` is tenant-bound. No multi-tenant production. DB init only on empty volume. App binds loopback only: private TLS/tunnel remains necessary for phone testing. Readiness is not capture acceptance, inference, adjudication, dispatch, payments, or production release.
